## What this means for Sherpa

1. Sherpa injections in this corpus: **0**, detected from the transcript record itself (`type: "custom_message"`, `customType: "sherpa-context"`), not from prose. The detector provably fires: the same corpus holds 995 `j01n`, 2 `j01n-peer-spawn-budget` and 1 `codemode-store` custom messages. So the extension was not active on the measuring host and there is no evidence yet of savings in either direction — P0-1 exists to create it.
   Assistant text mentioning "sherpa" in the same corpus: 0. That is reported separately and proves nothing either way; it is not the evidence used above.
2. bash is the largest source and its **median is 215 tokens**. The 12 000-char guard can never fire on a distribution like that. The cost is 3 000 small results re-read on every following turn, so the lever is fewer calls and shorter results — not summarising large ones.
3. read is only 386 calls but 69.5 M amortized: a large read is paid for hundreds of times. Keeping `read` exempt from the guard (current behaviour, index.ts:2669) is correct; the fix for read is fewer, better-targeted reads.
4. j01n (786 calls, median 40) is the shape to copy: a tool that returns small structured answers gets used constantly.
5. codemode is cheap per call and rarely used: 0.8 % of paid input across 175 calls in 12 of 98 sessions, with `searchTools` used 0 times and `models.classify` 0 times. The mechanism works; adoption does not happen by itself, which is why P0-4 proposes registering the tool with `codemode` exposure rather than `deferred`.

## How to re-measure

```
npm run metrics                     # summary table
npm run metrics:json                # writes docs/metrics.json
node scripts/sherpa-metrics.mjs --root <dir>
```

Read-only. No dependencies. Reads `**/*.jsonl` under the given root and writes only when `--json` is passed.

Cost accounting note: amortized = result tokens × assistant turns that *strictly follow* the result in its session. A result in the final turn is followed by nothing and is charged zero — 2 such results exist in this corpus. An earlier revision of this script charged a minimum of one turn, which inflated exactly those results; the number above is the corrected one and `scripts/sherpa-metrics.test.mjs` pins the behaviour.

```
npm run metrics:test                # 4 tests: injection vs mention, final-turn zero charge, two-turn charge, report shape
```
